Project Silkworm

An automated pipeline that spins out a growing DPO preference dataset. The same model answers every prompt twice under two system prompts, one expert and one terse, and the gap between the answers becomes the training signal. No human annotation is needed.

How it works

A loop that generates, filters and uploads

01

Sample a prompt

topics.py picks a domain, a topic (about 50 per domain) and one of 30 prompt templates, such as “What is {topic} and why does it matter?”

02

Generate twice

generator.py asks Llama 3.1 8B Instruct through the Hugging Face Inference API: once as a thorough expert (chosen, up to 512 tokens) and once as a hurried assistant (rejected, up to 256 tokens).

03

Filter

A pair is dropped if the chosen answer is under 200 characters, the rejected under 30, or the two are identical.

04

Skip duplicates

Prompts that are already in the dataset are skipped, so the dataset only ever grows with new rows.

05

Batch and upload

Accepted pairs go to a pending file. Every 50 pairs, uploader.py merges them into a Parquet file and pushes it to the Hugging Face Hub.

06

Watch it run

main.py shows a live terminal dashboard. Ctrl+C stops cleanly and uploads the final batch.

The dataset

Use it, with the licences in view

Five columns

prompt, chosen, rejected, topic and timestamp. Load it with load_dataset("iPwnds/Project-Silkworm") and use it straight away.

Built for DPO

The format works with TRL's DPOTrainer, so it plugs into preference-tuning pipelines without conversion.

Limitations

What the data is, and is not

Synthetic pairs

“Chosen” means “answered under the expert prompt”, not human-verified correctness, so answers can contain factual errors.

Mostly a length preference

The rejected side is deliberately low quality, so a model trained on it learns mostly a length and effort preference.

One model

Everything is generated by a single 8B model, so the dataset inherits that model's biases and gaps.

Configuration

  • HF_MODEL sets the generation model
  • UPLOAD_EVERY defaults to 50 pairs
  • MIN_CHOSEN_LENGTH 200 and MIN_REJECTED_LENGTH 30
  • REQUEST_DELAY defaults to 1.5 seconds

Quick start

  • Clone the repo and create a virtual environment
  • pip install -r requirements.txt
  • Copy .env.example to .env and set HF_TOKEN and HF_DATASET_REPO
  • python main.py

Project layout

  • generator.py chosen and rejected generation, quality filter
  • topics.py topic lists and prompt templates
  • uploader.py local storage, stats and Hub upload
  • tests/ covers sampling, the filter and storage
